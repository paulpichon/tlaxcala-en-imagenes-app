## 1. AuthContext (`src/context/AuthContext.tsx`)

### Propósito
Maneja la autenticación del usuario. Proporciona el estado del usuario logueado, funciones de login/logout, actualización de datos, y un wrapper de fetch con renovación automática de tokens.

### Estado
```typescript
interface IAuthContext {
  user: UsuarioLogueado | null;     // Datos del usuario logueado
  loading: boolean;                  // true mientras se verifica la sesión inicial
  login: (user: UsuarioLogueado) => void;
  logout: () => void;
  fetchWithAuth: (input: RequestInfo, init?: RequestInit) => Promise<Response>;
  updateUser: (newData: Partial<UsuarioLogueado>) => void;
}
```

### Acciones
| Acción | Descripción |
|--------|-------------|
| `login(user)` | Establece el usuario en el estado. Limpia `localStorage` y `sessionStorage` de datos de recuperación de contraseña. |
| `logout()` | Hace POST a `/api/auth/logout` con credenciales y luego establece `user` a `null`. |
| `fetchWithAuth(input, init)` | Wrapper de `fetch` que incluye `credentials: 'include'`. Si obtiene 401, intenta refrescar el token automáticamente. Si el refresh falla, cierra la sesión. |
| `updateUser(newData)` | Actualiza parcialmente los datos del usuario en memoria. |

### Efectos secundarios
- **Inicialización:** Al montar el provider, hace GET a `/api/auth/me`. Si recibe 401, intenta refrescar el token con `/api/auth/refresh` y re-intenta la petición.
- **Control de concurrencia en refresh:** Usa `useRef` para evitar múltiples refrescos simultáneos. Si ya hay un refresh en curso, las llamadas adicionales esperan la misma promesa.

### Dependencias
- `UsuarioLogueado`, `IAuthContext` desde `@/types/types`

### Hook de consumo
```typescript
export const useAuth = () => { ... }
// Lanza error si se usa fuera de AuthProvider
```

## 2. FavoritoContext (`src/context/FavoritoContext.tsx`)

### Propósito
Maneja el estado de favoritos para las publicaciones. Permite agregar o quitar publicaciones de favoritos.

### Estado
```typescript
interface FavoritoContextType {
  favoritosMap: Record<string, boolean>;   // posteoId → es favorito?
  loadingMap: Record<string, boolean>;     // posteoId → está cargando?
  toggleFavorito: (posteoId: string, autorId: string, initialFavorito?: boolean) => Promise<void>;
}
```

### Acciones
| Acción | Descripción |
|--------|-------------|
| `toggleFavorito(posteoId, autorId, initialFavorito?)` | Si el posteo es favorito, hace DELETE a `/api/favoritos/:id`. Si no, hace POST a `/api/favoritos/:id` con `autorId`. Actualiza `favoritosMap` según la respuesta (`"Agregado en Favoritos"` o `"Eliminado de Favoritos"`). |

### Dependencias
- `useAuth` (fetchWithAuth)

### Hook de consumo
```typescript
export const useFavorito = () => { ... }
```

## 3. FollowContext (`src/context/FollowContext.tsx`)

### Propósito
Maneja el estado de "seguir/dejar de seguir" usuarios.

### Estado
```typescript
interface FollowContextType {
  isFollowingMap: Record<string, boolean>;   // userId → lo sigue?
  loadingMap: Record<string, boolean>;       // userId → está cargando?
  toggleFollow: (userId: string, initialFollowing?: boolean) => Promise<void>;
}
```

### Acciones
| Acción | Descripción |
|--------|-------------|
| `toggleFollow(userId, initialFollowing?)` | Si actualmente sigue al usuario, hace DELETE a `/api/followers/unfollow/:userId`. Si no, hace POST a `/api/followers/follow/:userId`. Actualiza `isFollowingMap` con el nuevo estado. |

### Dependencias
- `useAuth` (fetchWithAuth)

### Hook de consumo
```typescript
export const useFollow = () => { ... }
```

## 4. NotificacionesContext (`src/context/NotificacionesContext.tsx`)

### Propósito
Gestiona el contador de notificaciones no leídas y proporciona una función para refrescarlo.

### Estado
```typescript
interface NotificacionesContextType {
  totalNoLeidas: number;
  setTotalNoLeidas: React.Dispatch<React.SetStateAction<number>>;
  refrescarNotificaciones: () => Promise<void>;
}
```

### Acciones
| Acción | Descripción |
|--------|-------------|
| `refrescarNotificaciones()` | Hace GET a `/api/notificaciones/nuevas-notificaciones` y actualiza `totalNoLeidas` con el valor recibido. |

### Efectos secundarios
- Al montar el provider (si hay usuario), llama a `refrescarNotificaciones()`.
- Configura un intervalo que refresca automáticamente cada 60 segundos mientras haya usuario logueado.

### Dependencias
- `useAuth` (fetchWithAuth, user)

### Hook de consumo

## 5. NuevosUsuariosContext (`src/context/NuevosUsuariosContext.tsx`)

### Propósito
Obtiene y provee la lista de usuarios recién registrados para mostrarlos como sugerencias de seguimiento.

### Estado
```typescript
type NuevosUsuariosContextType = {
  usuarios: UsuarioNuevo[];      // Lista de usuarios nuevos
  loading: boolean;              // Estado de carga
  reload: () => void;            // Recargar manualmente
};
```

### Tipo de datos
```typescript
type UsuarioNuevo = {
  nombre_completo: { nombre: string; apellido: string };
  imagen_perfil: { secure_url: string };
  url: string;
  _id: string;
  isFollowing: boolean;
};
```

### Acciones
| Acción | Descripción |
|--------|-------------|
| `reload()` | Vuelve a obtener la lista de nuevos usuarios desde el backend. |

### Efectos secundarios
- Cuando `authLoading` termina y hay usuario logueado, hace GET a `/api/usuarios/registrados/nuevos-usuarios-registrados`.
- Cuando no hay usuario, limpia la lista.
- Dependencia: `user?._id` (se recarga si cambia el usuario).

### Dependencias
- `useAuth` (fetchWithAuth, user, loading: authLoading)

### Hook de consumo
```typescript
export const useNuevosUsuarios = () => { ... }
```

## 6. PublicidadContext (`src/context/PublicidadContext.tsx`)

### Propósito
Maneja un carrusel de anuncios publicitarios con rotación automática cada 8 segundos.

### Estado
```typescript
interface PublicidadContextType {
  anuncioActual: (typeof anuncios)[number];  // Anuncio actual
  indice: number;                              // Índice actual
  pausar: () => void;                         // Pausar rotación
  reanudar: () => void;                       // Reanudar rotación
}
```

### Anuncios (hardcodeados)
Tres anuncios con imagen de Cloudinary y URL de destino:
1. Restaurante Olivares (enlace a linktr.ee)
2. Lena y Olivo (enlace a lenayolivo.com.mx)
3. Panadería Brindisi (enlace a Instagram)

### Acciones
| Acción | Descripción |
|--------|-------------|
| `pausar()` | Limpia el intervalo de rotación. |
| `reanudar()` | Reinicia el intervalo de 8 segundos. |
| `anuncioActual` | Devuelve el anuncio en el índice actual. |

### Efectos secundarios
- Al montar, inicia la rotación automática.
- Al desmontar, limpia el intervalo.

### Hook de consumo
```typescript
export const usePublicidad = () => { ... }
```
