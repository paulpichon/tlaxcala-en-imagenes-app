# Arquitectura del Proyecto — TlaxApp

**Fecha:** 2026-07-07

---

## 1. Patrón Arquitectónico

El proyecto utiliza **Next.js 16 con App Router** y sigue un patrón **híbrido** que combina:

- **Enrutamiento basado en sistema de archivos (file-system routing):** Cada directorio dentro de `src/app/` representa una ruta.
- **Grupos de rutas (Route Groups):** Uso de `(perfil)/` para agrupar rutas sin afectar la URL.
- **Layouts anidados:** Cada sección protegida (inicio, favoritos, notificaciones, configuración, perfil, posteo) tiene su propio `layout.tsx` que envuelve el contenido con `ProtectedRoute` y proveedores de contexto específicos.
- **Server Components por defecto:** Las páginas son Server Components que importan Client Components para la interactividad.
- **Client Components mínimos:** Solo los componentes que necesitan interactividad (hooks, estado, eventos) llevan la directiva `'use client'`.


### Rutas protegidas vs públicas

| Tipo | Rutas |
|------|-------|
| **Públicas** | `/`, `/cuentas/*`, `/contacto`, `/legal/*`, `/que-es-tlaxapp` |
| **Protegidas** (requieren auth) | `/inicio`, `/favoritos`, `/notificaciones`, `/configuracion/*`, `/[url]`, `/posteo/[idposteo]` |

## 3. Jerarquía de Providers (Layout Raíz)

El layout raíz (`src/app/layout.tsx`) anida 5 context providers en este orden:

```
<html lang="es">
  <body>
    <AuthProvider>              ← Autenticación (JWT, fetchWithAuth)
      <NotificacionesProvider>  ← Contador de notificaciones no leídas
        <FollowProvider>        ← Estado de "seguir/dejar de seguir"
          <NuevosUsuariosProvider>  ← Lista de nuevos usuarios registrados
            <PublicidadProvider>    ← Carrusel de anuncios publicitarios
              {children}
            </PublicidadProvider>
          </NuevosUsuariosProvider>
        </FollowProvider>
      </NotificacionesProvider>
    </AuthProvider>
  </body>
</html>
```

### Providers anidados por sección (en layouts secundarios)

Cada layout de sección protegida envuelve su contenido con:

- **`ProtectedRoute`** — Redirige a `/cuentas/login` si no hay sesión.
- **`FavoritoProvider`** — Estado de favoritos para la sección.

Secciones que incluyen `FavoritoProvider`:
- `/inicio/layout.tsx`
- `/favoritos/layout.tsx`
- `/notificaciones/layout.tsx`
- `/configuracion/layout.tsx`
- `/(perfil)/[url]/layout.tsx`
- `/posteo/[idposteo]/layout.tsx`

## 4. Flujo de Datos

### 4.1 Autenticación

```
Usuario → Login → API (POST /api/auth/login) → Cookie (JWT)
  ↓
AuthContext.Provider
  ├── user: UsuarioLogueado | null
  ├── loading: boolean
  ├── login(user) → setUser + limpia storage
  ├── logout() → POST /api/auth/logout → setUser(null)
  ├── fetchWithAuth() → fetch con credentials: 'include' + refresh automático en 401
  └── updateUser() → actualización parcial
```

### 4.2 Feed de Publicaciones (Scroll Infinito)

```
PublicacionUsuario (page)
  └── useInfinitePosts(initialUrl)
        ├── fetchWithAuth → GET /api/posteos
        ├── Intersección Observer detecta fondo
        ├── Acumula posts en estado local
        └── Retorna: posts[], loading, observerRef, finished
            └── PosteoCard (por cada post)
                  ├── LikeButton → useLikes(postId)
                  ├── FollowButton → useFollow (context)
                  ├── FavoritoButton → useFavorito (context)
                  ├── ComentariosModal → useComentarios(postId)
                  └── ModalOpcionesPublicacion
```

### 4.3 Favoritos

```
FavoritoContext.Provider
  ├── favoritosMap: Record<posteoId, boolean>
  ├── loadingMap: Record<posteoId, boolean>
  └── toggleFavorito(posteoId, autorId, initial?)
        → POST /api/favoritos/:id (agregar)
        → DELETE /api/favoritos/:id (quitar)
```

### 4.4 Follow

```
FollowContext.Provider
  ├── isFollowingMap: Record<userId, boolean>
  ├── loadingMap: Record<userId, boolean>
  └── toggleFollow(userId, initial?)
        → POST /api/followers/follow/:userId
        → DELETE /api/followers/unfollow/:userId
```

## 6. Manejo de Imágenes (Cloudinary)

Todas las imágenes se sirven desde Cloudinary usando una función helper `getCloudinaryUrl()` que construye URLs manualmente (sin usar el componente `next/image` loader).

### Presets disponibles

| Preset | Dimensiones | Crop | Gravity | Calidad | Formato |
|--------|-------------|------|---------|---------|---------|
| `feed` | 600×600 | fill | face | 85 | null (sin f_auto) |
| `detalle` | 1080×1080 | pad | auto | 85 | null |
| `perfil` | 300×300 | thumb | center | 85 | null |
| `grid` | 300×300 | fill | face | 85 | null |
| `mini` | 60×60 | fill | face | 85 | null |

> **Importante:** Todos los presets omiten `f_auto` para evitar bugs de imágenes rotas. `remotePatterns` configurado en `next.config.ts` para `res.cloudinary.com`.

## 7. Consideraciones de Seguridad

1. **Autenticación basada en cookies:** El JWT se maneja mediante cookies HttpOnly (credenciales `include`).
2. **Refresh automático de tokens:** Si una petición recibe 401, `fetchWithAuth` intenta refrescar el token antes de redirigir al login.
3. **Protección de rutas:** `ProtectedRoute` redirige a `/cuentas/login` si no hay sesión y muestra un spinner mientras carga.
4. **Redirección para usuarios autenticados:** `AlreadyAuthRedirect` redirige a `/inicio` si el usuario ya tiene sesión activa.
5. **No indexación de páginas privadas:** Las rutas protegidas tienen `robots: { index: false }`.
6. **Validación de formularios:** Uso de Zod para validar datos del lado del cliente antes de enviar al servidor.
