## Migraciones importantes

### TypeScript 6.0.3 → 7.0.2 (Major)

- **Ruta de migración:** Requiere revisión manual — TypeScript 7 introduce breaking changes. Consultar las release notes oficiales: https://devblogs.microsoft.com/typescript/
- **Impacto potencial:** Cambios en tipos, posiblemente en configuración de tsconfig, y nuevas features del lenguaje.
- **Acción recomendada:** Diferir esta actualización hasta después de resolver las vulnerabilidades críticas. Programar una sesión de migración dedicada.

### Next.js 16.2.10 → 16.2.12 (Patch con parches de seguridad críticos)

- **Ruta de migración:** `pnpm update next@16.2.12` — changelog en https://github.com/vercel/next.js/releases
- **Impacto:** Mínimo (cambio patch). Todos los CVEs se resuelven subiendo a >=16.2.11. La versión 16.2.12 es la más reciente estable.
- **Acción recomendada:** Actualizar **inmediatamente** como primera prioridad.

## Hallazgos adicionales

### 1. `@popperjs/core` como dependencia directa redundante

`@popperjs/core@2.11.8` está listado como dependencia directa en `dependencies` de `package.json`. Sin embargo:
- No se importa directamente en ningún archivo del proyecto (0 ocurrencias en `src/`).
- Bootstrap 5.3.8 ya lo incluye como dependencia propia (se resuelve en `node_modules` de todas formas).
- El proyecto solo importa `bootstrap/dist/css/bootstrap.min.css` — no usa los componentes JS de Bootstrap que requieren Popper (dropdowns, tooltips, popovers).

**Recomendación:** Eliminar `@popperjs/core` de `dependencies` en `package.json`. Si en el futuro se usan componentes JS de Bootstrap, se resolverá automáticamente desde la dependencia de Bootstrap.

### 2. Inconsistencia en imports de Bootstrap CSS

- `layout.tsx` importa `bootstrap/dist/css/bootstrap.min.css` (versión minificada)
- `page.tsx` y `ProtectedRoute.tsx` importan `bootstrap/dist/css/bootstrap.css` (versión sin minificar)
- `ConfirmacionPasswordRestablecidoClient.tsx` tiene un comentario con `import "bootstrap/dist/css/bootstrap.css"` comentado

Esto no causa errores pero es una inconsistencia. Se recomienda centralizar el import de Bootstrap CSS únicamente en `layout.tsx` y eliminar los imports redundantes en páginas individuales.

### 3. Uso de versiones exactas (pinned)

Todas las dependencias usan versiones exactas (ej: `"5.4.0"` en lugar de `"^5.4.0"`). Esto es una elección de diseño válida que garantiza builds reproducibles, pero requiere actualizaciones manuales explícitas. No hay problema con esto dado que `pnpm-lock.yaml` ya garantiza reproducibilidad, pero las versiones exactas en `package.json` son redundantes con el lockfile.

### 4. Sin lockfile duplicado

No se encontró `package-lock.json`. Solo existe `pnpm-lock.yaml`, consistente con el gestor declarado. No hay drift.

### 5. Sin scripts de lint, typecheck ni tests

El proyecto no tiene configurados ESLint, Prettier, typecheck ni tests. Esto es un hallazgo de calidad, no directamente de seguridad, pero se menciona porque:
- `typescript@6` tiene type-checking que podría detectar errores.
- No hay `tsc --noEmit` configurado.
- No hay `lint` ni `format` scripts.
