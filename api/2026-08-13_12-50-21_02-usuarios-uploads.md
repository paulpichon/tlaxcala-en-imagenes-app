## GET /api/usuarios/:url

**Descripción:** Obtiene el perfil público de un usuario por su slug/URL, enriquecido con totales de posteos, seguidores, seguidos y si el autenticado lo sigue. Soporta **redirección 200 permanente** si la URL está en `url_history`.
**Archivo de ruta:** `routes/usuarios.js:18`
**Controlador:** `controllers/usuarios.js` — `usuarioGet` (línea 32)

### Autenticación y permisos
- Requiere token: **Sí** (accessToken en cookie)
- Middleware de auth: `verificarTokenSesion`

### Middlewares (en orden)
1. `verificarTokenSesion`
2. `check('url', 'La URL no es valida').trim()`
3. `validarUrlUsuario` (`middlewares/validar-url-usuario.js:4`)
4. `validarCampos`

### Parámetros de entrada
| Ubicación | Campo | Tipo | Requerido | Validación exacta |
|---|---|---|---|---|
| params | `url` | string | Sí | `trim()`, debe existir en BD |

### Ejemplo de response — éxito
- Código de estado: `200`

```json
{
  "success": true,
  "data": {
    "usuario": {
      "_id": "664a1b2c3d4e5f6a7b8c9d0e",
      "nombre_completo": { "nombre": "Juan", "apellido": "Pérez" },
      "lugar_radicacion": { "claveEntidad": 29, "nombreEntidad": "Tlaxcala", "claveMunicipio": "001", "nombreMunicipio": "Apizaco" },
      "imagen_perfil": { "secure_url": "https://...", "public_id": "..." },
      "url": "juan-perez",
      "totalPosteos": 25,
      "totalSeguidores": 120,
      "totalSeguidos": 45,
      "isFollowing": true
    }
  }
}
```

### Ejemplo de response — redirección por URL histórica
- Código de estado: `200` + header `Location: /api/usuarios/<urlActual>`

```json
{
  "success": true,
  "msg": "La URL ha cambiado",
  "data": { "urlActual": "juan-perez-7a3f9", "redirect": "permanent" }
}
```

### Códigos de error posibles
| Status | code | title | detail | Dónde se lanza |
|--------|------|-------|--------|----------------|
| 401 | `UNAUTHORIZED` | Authentication Required | Token inválido o ausente | `verificarTokenSesion` |
| 404 | `NOT_FOUND` | Resource Not Found | `El usuario con URL "xxx" no existe` | `middlewares/validar-url-usuario.js:28,32` |
| 401 | `UNAUTHORIZED` | Authentication Required | `El usuario con URL "xxx" no ha verificado su cuenta` | `middlewares/validar-url-usuario.js:36` |
| 401 | `UNAUTHORIZED` | Authentication Required | `El usuario con URL "xxx" no ha activado su cuenta` | `middlewares/validar-url-usuario.js:40` |
| 403 | `FORBIDDEN` | Forbidden | `El usuario con URL "xxx" tiene la cuenta suspendida` | `middlewares/validar-url-usuario.js:44` |

### Notas para el Frontend
- La URL es un único segmento (el slug sanitizado nunca contiene `/`).
- Si la URL está en `url_history` de un usuario **activo** → `200` + `Location`. Si el dueño histórico está inactivo/eliminado/suspendido → `404` (privacidad).
- `isFollowing` indica si el autenticado sigue al dueño del perfil.

## POST /api/usuarios

**Descripción:** Registra un nuevo usuario. Genera URL única, hashea password, envía correo de verificación y devuelve un token opaco para `sessionStorage`.
**Archivo de ruta:** `routes/usuarios.js:30`
**Controlador:** `controllers/usuarios.js` — `usuariosPost` (línea 75)

### Autenticación y permisos
- Requiere token: **No**
- Middleware de auth: Ninguno

### Rate limiting
- `registroLimiter`: 3 registros / 1 hora → `REGISTER_BLOCKED`

### Middlewares (en orden)
1. `registroLimiter`
2. `check('nombre_completo.nombre', ...).trim().notEmpty().isLength({ min: 1, max: 60 }).matches(/^[a-zA-Z0-9áéíóúñÁÉÍÓÚÑ .'\-]+$/)`
3. `check('nombre_completo.apellido', ...)` (igual)
4. `check('correo', 'El correo no es valido').isEmail()`
5. `check('correo').custom(validarCorreoUsuario)` — no duplicado
6. `check('password').trim().isLength({ min: 8 }).matches(/^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?=.*[!@#$%^&*(),.?":{}|<>_\-+=\[\]])/)`
7. `check('estatus', ...).optional().trim().isNumeric()`
8. `check('intentos_login', ...).optional().trim().isNumeric()`
9. `validarCampos`

### Parámetros de entrada
| Ubicación | Campo | Tipo | Requerido | Validación exacta |
|---|---|---|---|---|
| body | `nombre_completo.nombre` | string | Sí | 1–60 chars, regex `^[a-zA-Z0-9áéíóúñÁÉÍÓÚÑ .'\-]+$` |
| body | `nombre_completo.apellido` | string | Sí | 1–60 chars, mismo regex |
| body | `correo` | string | Sí | `isEmail()`, único en BD |
| body | `password` | string | Sí | min 8 + 1 mayúscula + 1 minúscula + 1 número + 1 especial |
| body | `estatus` | number | No | `isNumeric()` |
| body | `intentos_login` | number | No | `isNumeric()` |

### Ejemplo de request
```json
{
  "nombre_completo": { "nombre": "Juan", "apellido": "Pérez" },
  "correo": "juan@ejemplo.com",
  "password": "MiPassword123!"
}
```

### Ejemplo de response — éxito
- Código de estado: `200`

```json
{ "success": true, "data": { "token": "e0f1a2b3c4d5e6f7a8b9c0d1e2f3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c8d9e0f1" } }
```

### Códigos de error posibles
| Status | code | title | detail | Dónde se lanza |
|--------|------|-------|--------|----------------|
| 422 | `VALIDATION_FAILED` | Validation Failed | Errores de campos | express-validator |
| 409 | `CONFLICT` | Conflict | `El correo ya está registrado en la base de datos` | `middlewares/validar-campos.js:18` |
| 429 | `REGISTER_BLOCKED` | Rate Limit Exceeded | `Demasiadas cuentas creadas desde esta conexión...` | `middlewares/rate-limiter.js:86-98` |
| 500 | `INTERNAL_ERROR` | Internal Server Error | `Hubo un problema al procesar la solicitud` | `controllers/usuarios.js:122` |

### Notas para el Frontend
- **Regex de password:** `/^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?=.*[!@#$%^&*(),.?":{}|<>_\-+=\[\]])/`.
- `data.token` es un **token opaco hex** (no JWT) para sessionStorage.
- **Efecto secundario:** `estatus: 0`, `email_validated: false`, URL/slug única (`helpers/crear-url-usuario.js`), password bcrypt salt 10, correo de verificación.
- **⚠️ A notar:** el `save()` solo ocurre si `envioCorreoVerificacion` retorna `true` (`controllers/usuarios.js:111-113`). Si el envío falla, el usuario no se guarda pero igual responde `200` con token.

## PUT /api/usuarios/update

**Descripción:** Actualiza datos del usuario autenticado (whitelist). Puede regenerar la URL/slug si cambia `nombre_completo` (cooldown 30 días).
**Archivo de ruta:** `routes/usuarios.js:65`
**Controlador:** `controllers/usuarios.js` — `usuariosPut` (línea 130)

### Autenticación y permisos
- Requiere token: **Sí** (accessToken en cookie)
- Middleware de auth: `verificarTokenSesion` → `req.usuario`

### Middlewares (en orden)
1. `verificarTokenSesion`
2. Validaciones express-validator (todas opcionales)
3. `validarCampos`

### Parámetros de entrada
| Ubicación | Campo | Tipo | Requerido | Validación exacta |
|---|---|---|---|---|
| body | `nombre_completo.nombre` | string | No | `optional().trim().notEmpty().isLength({min:1,max:60}).matches(...)` |
| body | `nombre_completo.apellido` | string | No | igual que nombre |
| body | `password` | string | No | `optional().trim().isLength({ min: 8 })` |
| body | `lugar_radicacion.nombreEntidad` | string | No | `optional().notEmpty()` |
| body | `lugar_radicacion.claveMunicipio` | string | No | `optional().notEmpty()` |
| body | `lugar_radicacion.nombreMunicipio` | string | No | `optional().notEmpty()` |
| body | `genero` | string | No | `optional().isIn(['MASCULINO', 'FEMENINO', 'PREFIERO NO DECIR'])` |
| body | `fecha_nacimiento` | date | No | `optional().isDate()` |

### Ejemplo de request
```json
{
  "nombre_completo": { "nombre": "Juan Carlos", "apellido": "Pérez López" },
  "genero": "MASCULINO",
  "fecha_nacimiento": "1995-06-15",
  "lugar_radicacion": { "nombreEntidad": "Tlaxcala", "claveMunicipio": "001", "nombreMunicipio": "Apizaco" }
}
```

### Ejemplo de response — éxito
- Código de estado: `200`

```json
{
  "success": true,
  "msg": "Usuario actualizado",
  "data": {
    "usuario": {
      "_id": "664a1b2c3d4e5f6a7b8c9d0e",
      "nombre_completo": { "nombre": "Juan Carlos", "apellido": "Pérez López" },
      "lugar_radicacion": { "claveEntidad": 29, "nombreEntidad": "Tlaxcala", "claveMunicipio": "001", "nombreMunicipio": "Apizaco" },
      "correo": "juan@ejemplo.com",
      "url": "juan-carlos-perez-lopez",
      "genero": "MASCULINO",
      "fecha_nacimiento": "1995-06-15T00:00:00.000Z",
      "nombre_completo_changed_at": "2026-08-13T12:00:00.000Z"
    }
  }
}
```

### Códigos de error posibles
| Status | code | title | detail | Dónde se lanza |
|--------|------|-------|--------|----------------|
| 401 | `UNAUTHORIZED` | Authentication Required | Token inválido o ausente | `verificarTokenSesion` |
| 422 | `VALIDATION_FAILED` | Validation Failed | Errores de campos | express-validator |
| 404 | `NOT_FOUND` | Resource Not Found | `Usuario no encontrado` | `controllers/usuarios.js:154` |
| 429 | `RATE_LIMIT_EXCEEDED` | Rate Limit Exceeded | `Solo puedes cambiar tu nombre y URL una vez cada 30 días` | `controllers/usuarios.js:172` (con `retry_after`) |
| 500 | `INTERNAL_ERROR` | Internal Server Error | `Hubo un problema al procesar la solicitud` | `controllers/usuarios.js:234` |

### Notas para el Frontend
- **Whitelist:** solo `nombre_completo`, `lugar_radicacion`, `genero`, `fecha_nacimiento` (`controllers/usuarios.js:24-29`). Otros campos (excepto `password`) se ignoran.
- `_id`, `correo` y `url` (directa) no son editables.
- **Regeneración de URL:** si `nombre_completo` cambia, se regenera el slug. Cooldown **30 días** salvo el primer cambio post-registro. La URL anterior se empuja a `url_history`.
- La imagen de perfil **no** se actualiza aquí.

## DELETE /api/usuarios/delete

**Descripción:** Elimina la cuenta del usuario autenticado (soft delete) con transacción MongoDB. Marca eliminado al usuario y a todos sus datos relacionados.
**Archivo de ruta:** `routes/usuarios.js:97`
**Controlador:** `controllers/usuarios.js` — `usuariosDelete` (línea 242)

### Autenticación y permisos
- Requiere token: **Sí** (accessToken en cookie)
- Middleware de auth: `verificarTokenSesion`

### Middlewares (en orden)

### Parámetros de entrada

|---|---|---|---|---|

### Ejemplo de response — éxito
- Código de estado: `200`

```json
{ "success": true, "msg": "Cuenta eliminada exitosamente. Tus datos serán eliminados permanentemente en unos días." }
```

### Códigos de error posibles
| Status | code | title | detail | Dónde se lanza |
|--------|------|-------|--------|----------------|
| 401 | `UNAUTHORIZED` | Authentication Required | Token inválido o ausente | `verificarTokenSesion` |

| 404 | `NOT_FOUND` | Resource Not Found | `Usuario no encontrado` | `controllers/usuarios.js:270` |

### Notas para el Frontend
- **Transacción MongoDB atómica:** soft delete de usuario + posteos + follows + likes + notificaciones + favoritos + comentarios. Rollback total si falla.
- **Efectos:** `estatus: 4`, `isDeleted: true`, `deletedAt`; posteos/comentarios con `deleteReason: "accountDeletion"`; decrementa `comentariosCount`; cierra sesión.
- Un cron job elimina físicamente tras el período de retención.

## PUT /api/uploads/:coleccion

**Descripción:** Actualiza la imagen de perfil del usuario autenticado. Sube a Cloudinary (raw) y elimina la anterior (si no es la default).
**Archivo de ruta:** `routes/uploads.js:17`
**Controlador:** `controllers/uploads.js` — `actualizarImagen` (línea 9)

### Autenticación y permisos
- Requiere token: **Sí** (accessToken en cookie)
- Middleware de auth: `verificarTokenSesion`

### Rate limiting
- `imagenPerfilLimiter`: 10 req / 15 min → `IMAGEN_BLOCKED`

### Middlewares (en orden)
1. `imagenPerfilLimiter`
2. `verificarTokenSesion`
3. `upload.single('img')` — Multer: memoria, 8 MB, jpg/jpeg/png/webp (`helpers/multer.js`)
4. `validarCampoImg` — valida que `req.file` exista
5. `validarImagenesMulter` — maneja errores de Multer
6. `check('coleccion').custom(c => coleccionesPermitidas(c, ['usuarios']))`
7. `validarCampos`

### Parámetros de entrada
| Ubicación | Campo | Tipo | Requerido | Validación exacta |
|---|---|---|---|---|
| params | `coleccion` | string | Sí | Debe ser `'usuarios'` |
| multipart | `img` | File | Sí | jpg/jpeg/png/webp, máx 8 MB |

### Ejemplo de request
- `Content-Type: multipart/form-data`; campo `img`; imagen jpg/png/webp ≤ 8 MB.

### Ejemplo de response — éxito
- Código de estado: `200`

```json
{
  "success": true,
  "msg": "Imagen de perfil actualizada correctamente",
  "data": {
    "imagen_perfil": {
      "secure_url": "https://res.cloudinary.com/.../imagen.jpg",
      "public_id": "tlx-imagenes/imagenes-perfiles-usuarios/664a1b2c3d4e5f6a7b8c9d0e/<uuid>"
    }
  }
}
```

### Códigos de error posibles
| Status | code | title | detail | Dónde se lanza |
|--------|------|-------|--------|----------------|
| 400 | `BAD_REQUEST` | Bad Request | `La imagen excede el tamaño máximo permitido (8 MB)` | `middlewares/validar-imagen-posteo.js:27` |
| 404 | `NOT_FOUND` | Resource Not Found | `No hay ninguna imagen para subir` | `middlewares/validar-imagen-posteo.js:19` |
| 422 | `VALIDATION_FAILED` | Validation Failed | `La coleccion: xxx no esta permitida, se permiten: usuarios` | `helpers/colecciones-permitidas.js:10` |
| 400 | `BAD_REQUEST` | Bad Request | `No existe un usuario con el ID: xxx` | `controllers/uploads.js:24` |
| 429 | `IMAGEN_BLOCKED` | Rate Limit Exceeded | `Demasiadas subidas de imagen de perfil...` | `middlewares/rate-limiter.js:191-203` |
| 500 | `INTERNAL_ERROR` | Internal Server Error | `Error al actualizar la imagen` | `controllers/uploads.js:89` |

### Notas para el Frontend
- Formato `multipart/form-data`, campo `img`.
- Imagen subida **raw** (sin transformaciones); las transformaciones se aplican al vuelo en frontend vía `public_id`.
- Si la imagen anterior no es la default (`DEFAULT_USER_IMAGE`), se elimina de Cloudinary antes de subir la nueva.
- **⚠️ Verificar:** si el archivo tiene extensión/MIME no permitido, `multer.fileFilter` lanza `Error` sin `code` → termina como **500** (no 400).
